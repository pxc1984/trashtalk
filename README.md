# Trashtalk (или же @cutalkbot)

## Инструкции по запуску

Перед началом работы убедись, что у тебя установлены git и docker

1. склонируй репозиторий к себе
```
git clone https://github.com/pxc1984/trashtalk.git
```
2. Переключись в директорию и подними контейнеры через докер компоуз
```
docker compose up -d --build
```
3. У тебя появится директория `./exports`, помести в нее экспорты чатов на которых хочешь натренировать трештолк. Каждая директория с экспортом должна начинаться с `ChatExport_` и внутри содержать как минимум файл `result.json`.
4. Задай `BOT_TOKEN` в `.env` (копия `.env.example`) — без него inline-бот не запустится.

## Конфигурация генерации

Параметры генерации задаются через переменные окружения в `.env`:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `NGRAM_SIZE` | `3` | Старший порядок n-грамм для обучения и генерации |
| `MIN_NGRAM_SIZE` | `2` | Младший порядок для бэк-оффа: если точное продолжение неизвестно, генерация ищет его по более короткому префиксу |
| `GENERATION_TEMPERATURE` | `0.9` | Температура сэмплинга: `1.0` — пропорционально частотам, `<1` — концентрирует выбор, `>1` — добавляет разнообразия |
| `GENERATION_TOP_K` | `0` | Оставлять только top-K вероятных продолжений (`0` — выключено) |
| `GENERATION_TOP_P` | `0.9` | Nucleus-сэмплинг: минимальное множество кандидатов с накопленной вероятностью `top_p` (`1.0` — выключено) |
| `REPETITION_PENALTY` | `1.3` | Штраф на повторный выбор уже сгенерированных токенов — ломает марковские зацикливания (`>=1.0`) |
| `NUM_CANDIDATES` | `3` | Сколько кандидатов-продолжений сэмплировать и из каких выбирать лучший по качеству (best-of-N; `1` — выключено) |
| `MIN_GENERATION_TOKENS` | `4` | Минимум сгенерированных токенов до того, как бот остановится на границе предложения |
| `MAX_GENERATION_LENGTH` | `64` | Жёсткий лимит длины генерации |
| `HEARTBEAT_INTERVAL_SECS` | `60` | Как часто main-цикл пишет лог `alive` (для диагностики «тихого» падения в докере) |

## Архитектура

Код разбит на слои:

- `domain` — модели и доменная логика (`Token`, токенизация, параметры генерации, границы предложений);
- `application` — ядро генерации (бэк-офф, сэмплинг с температурой/top-k/top-p, остановка на границе) и обучение n-грамм;
- `infrastructure` — репозитории БД, чтение Telegram-экспортов, воркер инжеста;
- `bot` — Telegram inline-бот.
